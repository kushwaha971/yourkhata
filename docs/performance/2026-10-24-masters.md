# Categories and units · 24 Oct 2026 (09 §8.5, R-DEC-32, R-DEC-34)

Scope: `/items/masters` (`InventoryMastersPageContent`, `MasterFormDialog`), and
two small opt-in design-system additions it needed: `UbChipTabs size="sm"` and
`UbStatusBadge srLabel`. Price lists (§8.6) are NOT covered.

Who needs it: the owner at setup, rarely after. The job is short: find a
category or a unit, and add it when it is not there. Until now the page had one
Add in the page header that changed meaning with the tab, no search over 26
standard units, and an add form that sent a duplicate name to the server and
let it hand back the existing row without saying why nothing new appeared.

## What changed

- **Find → add.** Each section has its own search. When nothing matches, the
  section says so and offers "Add it as a category" (or unit); the dialog opens
  with what was typed. A short word becomes a unit's code (in capitals), a
  longer phrase its name.
- **Already exists, before sending.** The add forms check the name against the
  list the page already holds, by the server's own rule, and say "Already
  exists." instead of sending it. Moving a category to another parent re-checks
  the name, because the rule is per parent.
- **Sections.** Each section is a panel with its own + Add. A phone switches
  between them with small chips; a desktop shows both side by side.
- **Units.** Standard units are one group, each with a locked "Standard" badge;
  the shop's own are below under "Your units", which says so when there are
  none. The old "Custom" badge is gone: the group heading says it.

## Deviations and decisions recorded

1. **The add button names the kind, not the text.** A first version read
   "Add “Dry fruits”"; with a 60-character name that button ran off a 320 px
   phone. The sentence above it quotes the text, so the button says "Add it as a
   category".
2. **Order of units follows the spec**: standard first. A shop's own units are
   the ones it chose, and with 26 standard codes they sit below the fold on a
   phone; the search reaches them in one step. Recorded rather than reordered,
   because the spec is explicit.
3. **No rename or delete**, as the spec says (create-only at MVP).
4. **Test rows on the QA tenant.** The harness leaves its categories and units
   in the local QA book (create-only: nothing can remove them). They are named
   `QA85 …`.

## Found by looking

- The chip row was the landing page's 40 px pill with a 40 px target on a phone.
  `UbChipTabs` gained `size="sm"`: a 32 px face with the existing 44 px hit area.
- A long search pushed "Nothing matches “…”" off a 320 px phone as one unbroken
  word; it now wraps anywhere.
- The harness's first double-tap was not one: Playwright's click waits for the
  button to be enabled again, so the second click never raced the first. It now
  clicks twice inside one task, as a thumb does.

## Performance

Opening the page: from navigation start until the first category row is
visible, at 4x CPU throttle, against `dcaddbc` (dev before §8.4, same page as
before this piece). Each side had 6 opens per round, 2 rounds alternating old
and new, on a phone (390×780) and a desktop (1280×900). Script and raw numbers:
`data/2026-10-24-masters/`.

| | old median | new median | n per side | new range |
|---|---|---|---|---|
| Phone | 988 ms | 1,067 ms | 12 | 974–1,245 ms |
| Desktop | 1,013 ms | 1,088 ms | 12 | 962–1,389 ms |

**This piece is slower to open, by about 75 to 80 ms at 4x CPU** (roughly 20 ms
on an unthrottled device). The ranges overlap, but both medians moved the same
way, so I read it as a real cost, not noise. The cause is that both sections
are now in the page at once (26 standard units with badges, plus the
categories), and the route chunk grew 1.3 KB for the search and the chips.

The first measurement was worse on a desktop (+135 ms) and showed why: the
layout was chosen by a JavaScript media query, whose server answer is "phone",
so every desktop load hydrated the phone layout and then rebuilt the page. The
layout is CSS now (chips hidden from `lg`, both panels side by side), which
removed the rebuild; the numbers above are after that fix. Rendering only the
visible section would need the width before render, which is the flip just
removed; for a page used at setup I left it and record the cost.

Bundle: `/items/masters` route 57.3 → 58.6 KB, first load 298.9 → 300.4 KB.
Five other routes rounded over their ceilings by 0.0 KB, most likely through
`UbStatusBadge`'s new `srLabel`; not isolated. Each exceeded budget was raised
to the measured size plus 0.3 KB, with a note in `bundle-budgets.json`.
