HOW EACH PIECE IS DONE (the owner's rule, R-DEC-07, and the loop in CLAUDE.md):
review the spec, build, LOOK, report. After EACH piece (a screen, form, card,
drawer, sheet or dialog):
 1. Gates: `npx eslint --fix --max-warnings=0 <changed files>` (the full lint takes
    over 25 minutes in the cloud container; say so), `npm run type-check`, the
    full `npx jest`, the build (command below), `npm run bundle:check`,
    `npm run check:contrast`, and `npm run i18n:split && npm run i18n:check` after
    any locale change. Do not run jest and the build at the same time: a test
    writes a temporary probe file that the build's type check then trips on.
 2. Restart the frontend after every build (`./e2e/serve.sh`); a rebuild under a
    running server breaks it. API: `./e2e/serve-api.sh`; database:
    `service postgresql start`. Build command:
    NEXT_PUBLIC_API_BASE_URL=/api/v1 API_PROXY_TARGET=http://127.0.0.1:8000 \
    NEXT_PUBLIC_SW_ENABLED=false NEXT_PUBLIC_ANALYTICS_ENABLED=false npm run build
 3. Screenshots: add a `--piece=<name>` to e2e/revamp-shots.mjs and shoot
    390 and 320 px phones and 1024 and 1280 px desktop, light and dark, plus
    `--locale=hi` at 320 and 1280, in EVERY state (loading, empty, error, long
    names, ₹12,40,378.00, busy, saved). Sign-in: scale@digikhaato.test /
    Scale-Run-2026! (the seed_scale owner). Make contact sheets with `montage`
    and LOOK at every one. Copy them to /mnt/project-files/revamp/shots/<piece>/.
 4. Make the harness MEASURE, not read: computed colours, each label's contrast
    against what it sits on (>= 4.5:1), every text node against its own box (no
    cut or clamped word), page width against the viewport. F4's screenshots found
    three defects every unit test passed: dark rail labels at 1.4:1 in the light
    theme, a search field running edge to edge, and words cut by the rail width.
    Prove each new check FAILS on the old build before trusting it.
 5. Speed: `NODE_PATH=$(npm root -g) node e2e/perf-app.mjs --reps=3 --only=nav`
    with nothing else running; compare with the F4 numbers in
    docs/performance/2026-10-18-f4-app-button.md and the baseline
    docs/performance/2026-10-17-app-baseline.md. No speed claim without both.
 6. Every defect fixed gets a test that fails before the fix, with a docstring
