19–20 October 2026. R-DEC-16/20/21/22/23/24. This continues the existing revamp on dev. Scope: Shop Home, its shared header command search and existing payment/reminder/document entry points. This is not a whole-Shop or whole-app completion claim.

## Delivered behavior

The owner rejected the first identity-only/disclosure composition. It is superseded, and its provisional 8.76 score is withdrawn. The inspected reference is `docs/revamp/design/counter-mode.html` plus the owner's desktop/mobile screenshots. The remote artifact was unavailable to the web tool; no claim of inspecting a current remote revision. Subsequent owner choices override the prototype: search belongs in the global header, and the graph needs daily/weekly/monthly/yearly grouping rather than hourly.

- Desktop: global Find or start; Home header/actions; normal-weight rounded Repeat pills; ruled figures and compact graph; Register / Follow-ups / Insights beside independent customer/supplier lanes. The main panel sizes to its own content rather than stretching to the longer side column.
- Mobile: full-width search in the header; two general actions; one joined 2×2 figure card with internal dividers; two compact balance summaries; filled segmented tabs and a separate content card. Register rows lead with time, type, person and amount. Large amounts remain fully visible, with a smaller numeric size at narrow widths rather than ellipsis. The existing app navigation is retained; no phone bar on desktop.
- Graph: Last 7 days by default; This week (Monday through today), This month, This calendar year, All time, Custom. Independent Day / Week / Month / Year grouping, with over-120-bar groupings unavailable. This year defaults to months. Chart/table show the same server data; current incomplete period is marked so far. The compact filters use the shared UI kit, sit on one row, and draw at 32 px while retaining the existing touch-target treatment. The original extended analytics and period comparisons remain under More reports and comparisons.
- Find or start works throughout Shop using existing paged party/item/sales/purchase sources. Name/mobile, name + amount, amount, item and bill number lead to reviewed existing forms or original documents. A dual-role person has distinct Receive and Pay choices. Queries and cached/local results follow actor/business/revision scope; stale selections are blocked. Search has no financial POST.
- Item selection seeds a NEW invoice through the same extracted default-line mapping used by the normal item picker. Editing a line does not change the item's default price or an old invoice. A late lookup cannot replace manual input. Ordinary invoice autosave remains; item search does not issue a document.
- Repeat chooses the most-used recent person/category within 14 days and reads its latest eligible source. It copies proposed items/rates into a new reviewed form, retaining today's date and current editor context. Old document ids/numbers, supplier invoice references, due dates and payments are not copied. Repeat sales/purchase forms do not server-autosave; Save/Issue/Record is explicit. Expense repeats reuse the existing expense drawer and clear the old payment reference. Existing unsaved work wins over late source reads.
- Payment/reminder forms are dynamic and reused. Optional payment tradeRole narrows only callers that request it. Reminders stay editable, use Shop balances and never combine customer/supplier or other-app money.

## Financial sources and access

Today's Billed/Received and Shop cash use the existing dashboard. Paid out uses today's actual daily money-series point, not the seven-day total. Cash is signed cash by records, not a physical till count; opening cash is excluded. Omitted authorized figures remain omitted. Zero figures remain neutral.

BP-15 adds only `GET /reports/dashboard/counter`: private/no-store, tenant scoped, Shop-book gate and source permissions resolved through the existing per-app resolver. No models, migrations, posting endpoints, existing response shapes or Library/Lending contracts changed. It returns real Repeat sources and independent role lanes. The source uses `with_shop_facts`, never a combined contact balance.

Lane bands group each person's **net role balance by their oldest open bill**, as the visible caption states. They are not a historical invoice-aging allocation or an automatic settlement. A contact owing ₹1,000 as a customer and owed ₹600 as a supplier remains in both roles; no ₹400 net. An undated open bill is not labelled late. API tests reconcile the bands and verify tenant/Shop access and omission of unreadable sources.

Final bundle measurements and only the necessary budget changes are recorded below. Shared/framework ceilings are unchanged.

## Defects found and proof

- Old Home acceptance failed missing tabs and clipped 5,00,000 axis labels. Grouped/trend charts now derive the gutter from formatted ticks; fail-before unit checks cover this.
- Previous-actor chart results stayed local after session changes; a scope regression failed before the shared scope key was applied.
- Long command labels hid the recipient in an ellipsis; the wrapping regression failed before the optional shared-picker mode.
- `fit` tabs scrolled the phone on mount; fill/segmented tabs keep initial scroll at zero, asserted in the harness.
- Prior mobile geometry failed the new check: radius 0, gap 16, no internal borders, no filled tab rail. The corrected layout must pass the same computed checks.
- Prior graph filters failed the new 32 px geometry check at 36 px. Final checks require both controls on the same row and at most 33 px.
- The 320 px production sweep found cropped crore amounts and Retry in a narrow lane. Font sizing and wrapping were corrected; no amount is rounded or abbreviated to conceal the problem.
- Full tests caught missing lazy translation catalogues and the shell hard-coding an app name. The search owns its small catalogue; the shell reads the app manifest's capability.

## Honest limits and next work

This is not a pixel-identical copy of every prototype datum: live register data does not include payment status/item count for every event, so unavailable status pills are not invented; the existing recent-source feed remains the register's read. Follow-ups retain real existing overdue/order/low-stock facts, rather than a fabricated Shop promise copied from personal Udhaar. The cash figure opens the existing cashbook; a new physical cash-count workflow is not claimed. No automatic dual-role settlement, BP-10 historical role statement, personal per-user Udhaar model or omitted shell feature is smuggled into this delivery.

Physical Android/iOS installed-PWA lifecycle, TalkBack, large OS text and timed research with merchants remain unproven by desktop Chromium. Screenshots, computed contrast, overflow/text-node measurements and unit tests are complementary; none is a blanket certification of all APIs, all modules or all business edge cases.
